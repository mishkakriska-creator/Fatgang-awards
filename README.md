# FatGang Awards 2026
Независимая русскоязычная музыкальная премия. 
- Live: https://fatgang-awards.onrender.com
- Admin: /admin.html (пароль в Render)
- GitHub main автоматически разворачивается в Render, Node.js, Frankfurt, free.
- Supabase PostgreSQL via session pooler. CA: certs/prod-ca-2021.crt. Не публиковать DATABASE_URL, ADMIN_PASSWORD или SESSION_SECRET.
## Файлы
public/index.html, style.css, app.js — интерфейс. public/logo.webp — предоставленный логотип (оптимизирован для веба). nominees.json — категории и номинанты; item: {id,name,artist?,image?,audio?,works?: [{name,audio}]}, медиа в public. server.js — Express API, PostgreSQL, сессии, bcrypt. render.yaml — конфигурация.
## Требования владельца
Пять категорий: артист, продюсер, обложка, трек, альбом года. Один альбом в категории «Альбом года», до 3 разных номинантов в каждой из остальных категорий, один необратимый бюллетень в каждой категории на аккаунт и браузер. Сервер выдаёт подписанную cookie браузера, которая сохраняется после выхода. Уникальный индекс в ballots защищает от одновременных повторных запросов. 7 дней с VOTING_START (ISO дата/время). Не устанавливать до согласования. Регистрация только ник и пароль. Номинантов и медиа владелец передаёт для внесения в код. Админка только для результатов, не для изменения номинантов. Результаты не показывать публике до окончания. Дизайн: музыкальная премия в духе РЗТ, собственные цвета и оригинальный логотип FatGang.
## Защита голосования
Сервер сохраняет прежние ключи бюллетеней и выдаёт подписанную копию идентификатора для восстановления cookie через localStorage. Совпадение псевдонимного отпечатка в одной категории фиксируется в закрытом журнале. Уникальность бюллетеня обеспечивают ограничения PostgreSQL по аккаунту и ключу браузера. При полном сбросе хранилищ надёжно установить личность устройства невозможно.

Регистрация, вход и отправка голосов требуют одноразовую CAPTCHA. По умолчанию работает встроенная проверка по картинке. Для Cloudflare Turnstile создать Managed widget для fatgang-awards.onrender.com, добавить TURNSTILE_SITE_KEY и TURNSTILE_SECRET_KEY в Render Environment. Для другого домена также задать TURNSTILE_HOSTNAME. Сервер проверяет токен, домен и действие. Секретный ключ хранить только в окружении.

Лимиты запросов хранятся в PostgreSQL в виде HMAC-ключей. Для голосования IP используется только как сигнал массовой активности. Админка показывает часовые счётчики за 30 дней. В журнал не записываются пароли, адреса, исходные характеристики или идентификаторы устройств.

При запуске schema.sql транзакционно проверяет совместимость, добавляет поля и индексы, включает RLS и отзывает права публичных ролей для внутренних таблиц. Ошибка откатывает миграцию. Продакшен использует проверяемое TLS-соединение и постоянный SESSION_SECRET. Для тестов использовать отдельный PostgreSQL. VOTING_START устанавливается только владельцем по согласованию.

После входа или регистрации сервер связывает подписанный идентификатор браузера с аккаунтом. Для ранее открытых сессий привязка создаётся при следующем обращении. После истечения сессии пользователь входит в прежний аккаунт по паролю. Удаление обоих браузерных хранилищ сбрасывает идентификатор. Личный список показывает отправленные бюллетени с сервера, а неподтверждённые выборы живут в текущей вкладке.
